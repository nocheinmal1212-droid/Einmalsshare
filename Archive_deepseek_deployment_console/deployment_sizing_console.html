Memory and capacity

Model / accelerator Hint GBKV/rep GB Cap LBNodesCfg Status

Cap LB is an aggregate lower bound: it covers the documented device minimum and the larger of the recipe VRAM hint and the modelled workload KV, without assuming those are additive. It does not establish per-rank TP/DP/EP/PP residency, and it does not make a topology runnable. Hint is a recipe authoring heuristic whose margin composition is undefined; a hatched rail means no hint is published at all.

How this console relates to the Python

  
    
    
  • Same model, ported not reinterpreted. Every constant, rounding rule, issue code, and message here is transcribed from deepseek_deployment_sizing.py. Python's round-half-to-even and PEP 440 version ordering are reproduced rather than approximated.
    • 
    
  • Verified by differential test. A harness runs the Python CLI with --json across 60 parameter cases — dtype combinations, version edge cases, override sets, and every validation failure — and compares all 29,039 emitted fields. Floats agree exactly, not within a tolerance. Re-run it after any change to either implementation.
    • 
    
  • Where the console goes further than the CLI: a bad parameter fails one row here instead of aborting the whole run; rows expose the arithmetic behind their own figures; the flags that were hardest to remember (--service-rate, --replica-devices) became inputs inside the row they govern.
    • 
    
  • What deliberately stays empty. configured_required_hbm_gb, configured_headroom_gb, and configured_memory_fit are null in the Python by design, and they are null here. Filling them in would require inventing a composition for the recipe hint's margin that no source defines.
