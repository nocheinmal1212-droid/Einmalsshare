正式 Manual (English authoritative)

Files

  • kb-retrieval-harness.js — paste/run as an Edge DevTools Snippet.
  • This runbook — setup, pilot, recovery, and reconciliation instructions.

Prepare the script

Open kb-retrieval-harness.js and find FILE_NAMES_TEXT near the top. Replace the placeholder with one bare filename per line:

const FILE_NAMES_TEXT = String.raw`
        UN_GAAM_ALERT_2025_31.pdf
        GAAM_Alert_2025_31_Attachment_1.pdf
        `;

Paste names at column 1 without bullets, quotes, commas, agent prefixes, or surrounding whitespace. Exact duplicate lines are sent only once and listed in the audit. The script rejects path-like or whitespace-padded input.

Matching is case‑sensitive exact equality after one operation: the confirmed agent prefix is removed through the last forward slash in the returned file_name. Nothing else is normalized — no lowercasing, trimming, backslash handling, substrings, or fuzzy matching.

Capture the selected agent’s request template

Do this once for each selected agent/configuration:

  1. On the corporate Windows device, open the authenticated application in Edge.
  2. Select the agent and open a fresh conversation.
  3. Send one throwaway query.
  4. Open DevTools (F12 or Ctrl+Shift+I). In Network, select its POST /api/Prompt/ request and choose Copy as fetch.
  5. In DevTools Sources, create a Snippet, paste the complete harness, save (Ctrl+S), and run (Ctrl+Enter).
  6. In the Console, run: kb.armCopyAsFetchCapture()
  7. Paste the unedited Copy as fetch command and press Enter.

The harness intercepts the pasted command, extracts URL, headers, and payload, removes the Bearer value, and does not resend the throwaway request. Unrelated background fetches pass through normally.

Check the sanitized result:

kb.captureSummary()

If the token’s Local Storage key could not be selected uniquely:

kb.tokenCandidates()       // key names only; never token values
            kb.setTokenKey("exact-key-name")

The sanitized request template is saved in Local Storage for recovery after a reload. Capturing a different agent/configuration produces a separate state namespace.

Select the output

Preferred (verifies existing files and avoids overwriting different content):

await kb.pickFolder()

If managed policy blocks the directory picker, configure Edge to download without prompting into a dedicated empty folder, then use:

kb.useBrowserDownloads()

Browser‑download mode verifies the HTTP response and PDF bytes before clicking the download, but cannot verify the final disk write. Rows are reported as download_triggered, not downloaded.

Pilot, then run

Keep the application tab in the foreground. In Windows Settings → System → Power & battery → Screen and sleep, prevent sleep while plugged in for the duration of the run, if corporate policy permits.

Run the first 20 input rows through their complete retry ladder:

await kb.pilot(20)
            kb.report()
            kb.details()
            kb.exportState()

Inspect the downloaded files and audit before continuing. Then run the remainder:

await kb.run()

At the observed 2–4 minutes per model result, a clean 20‑file pilot (five four‑file batches) takes roughly 10–20 minutes. Unmatched‑file retries add time.

Each semantic attempt performs: token refresh → GET /api/Tools/GetSessionId → copy captured Prompt payload (replace content and model_params.user_session_id) → POST /api/Prompt/ → parse acknowledgement and persist prompt_resp_id → blocking GET /api/PrompResponse/{id} (note the missing t — this is the deployed path) → parse list_page_info → download cited PDFs via cookies (no Bearer header).

Partial batches are safe: matched files are saved; only unmatched filenames requeue. The initial and second semantic attempts use batches of up to four; the third and final attempt is a singleton.

Controls and recovery

kb.stop() // graceful stop after the current operation await kb.resume() // resume saved result GETs first, then downloads/queries kb.requeueDownloadFailures() // after fixing folder/network issues; then resume await kb.backfillUnmatchedCitations() // from v1.1.0 audit; no Prompt calls kb.report() // counts by per-file status kb.details("failed") // optional status filter kb.details("extra") // unmatched download references kb.exportState() // complete JSON audit trail kb.help() // command summary

State is rewritten in Local Storage after material transitions. After a page reload:

  1. Rerun the DevTools Snippet.
  2. Reselect the output folder with await kb.pickFolder() (directory handles are intentionally not persisted), or re‑enable browser‑download mode.
  3. Run await kb.resume().

If a Prompt acknowledgement had already been received, resume reissues /api/PrompResponse/{saved-id} before submitting anything new. kb.stop() is graceful and does not abort an active result GET, so it may take up to the current request’s five‑minute timeout to return.

A 401 is retried once after rereading Local Storage. A second 401 halts cleanly. A 429 honors Retry-After when present, otherwise backs off for 30, 60, 120, and 240 seconds while increasing the inter‑batch delay.

To remove only the current run’s saved state (downloaded files are not touched):

kb.resetCurrentState("RESET")

Resume and reload recovery belong to the same run and may reuse its saved citation URLs. To deliberately start a new independent run with the same agent and filename list, export the old audit and reset its state first.

Audit interpretation

downloadedPDF response verified and disk write completed. download_triggeredPDF response verified; browser download triggered, disk write not inspected. pendingWaiting for another semantic attempt. awaiting_resultPrompt accepted; saved prompt_resp_id is waiting or ready to resume. failedNo exact citation match after three semantic attempts. citedExact citation found; download remains retryable. download_failedAll configured download attempts exhausted. unavailableImmediate citation download returned 403. ambiguousExact filename resolved to more than one distinct document hash; candidates saved with suffix. extraVerified synthetic download for a citation hash that matched no expected line; filename prefixed with unmatched__.

Page‑level citations with the same document hash are downloaded once. Hashes are not used to merge different filenames — if a hash appears under two distinct exact names, both identities are preserved and the collision is flagged for review. This protects parent and attachment filenames from accidental conflation.

The exported JSON records every returned citation candidate, exact matches, page URLs, document hashes, download checks, errors, duplicate input lines, and cross‑filename hash collisions. Reconcile that export against the operator’s source list after each agent run.

certutil -hashfile "C:\path\to\file.pdf" SHA256
